# Preregistered response-cache scope counterexamples

2026-11-18. Original deterministic engineering experiment, not an Azure/Redis benchmark, deployed incident, LLM-quality study or semantic-cache replication. Question: can a cache hit bypass otherwise-correct source authorization or return an outdated grounded answer? Hypothesis: tenant scope isolates tenants, but does not alone handle different permissions inside one tenant, revocation or changed sources. Recompute authorized context before cache lookup and include its identity/version/content in the key to address these specific cases. This differs from the completed refund authorization and retry/fencing studies: the object being reused is a previously permitted answer, not a proposed side effect or overlapping worker write.

## Prototype and fixed interfaces

Implement only cache.py with standard-library Python. `Gateway(documents, grants, mode)` deep-copies inputs and owns a memory cache and deterministic answer-generation counter initially 0, exposed as generations in snapshots. Documents are a list of JSON dictionaries with nonempty id, tenant, query, integer version and string value; grants maps principal names to lists of allowed document IDs. Three modes: `query`, `tenant`, `context`. Tests and harness use only authored data. Principals and tenants supplied by the driver are trusted synthetic identities; this does NOT implement authentication or protect an arbitrary service against forged identities.

`ask(tenant, principal, query)` returns a JSON dictionary with exactly `status`, `body`, `cache_hit`. A permitted response has status 200, cache_hit bool, body containing exactly answer (the document value), document_id, document_version. Resolve an eligible document by matching tenant AND exact query AND an ID in the current principal's grant set. There is at most one eligible document per request in this fixed experiment. If there is none, return status 403, body None and cache_hit False. No denial is cached. If a request is answered from the source, increment generations by one; lookup/retrieval/authorization itself is not answer generation. No LLM or paid API is called: the answer is a deterministic stand-in for a grounded completion, isolating cache behavior.

Intentional baseline behavior: mode query first checks a cache keyed only by query and returns an existing body immediately, BEFORE resolving current authorization. Mode tenant likewise first checks (tenant,query). Both resolve authorization correctly on a miss, then store the answer under their respective key. Do not fix these deliberately incomplete baselines; their cache-hit bypass is the tested failure mode.

Mode context MUST resolve current authorized documents before lookup; reject with 403 if none. Its cache key includes tenant, query and the authorized document's id, version and value. It deliberately does not include principal identity, so two principals with exactly the same current authorized context may reuse the same response. The purpose is to test scope correctness, not turn caching off or isolate every user unnecessarily. Version AND content are included; a changed value without a version increment must invalidate this key too. Normal requests are synchronous with no concurrent mutation between context resolution and return. This does not test revocation races or distributed consistency.

`set_grants(principal, ids)` replaces that principal's grant set. `set_document(id, value, version)` updates only that document's value/version. Both setters return None. These are owned driver mutations; neither implicitly purges any cache, allowing key behavior to remain observable. `snapshot()` returns a deep copy `{documents: list sorted by id, grants: mapping to sorted unique lists, cache: list of response bodies sorted by document_id, document_version, answer, generations: integer}`. Cache response entries may have identical bodies; preserve them all. This snapshot does not disclose implementation keys and therefore permits valid alternative key encodings. Return values are deep copies so client mutation cannot poison internal state. Unknown mode raises ValueError.

## Fixed 144-trial matrix

Eight synthetic fixture variants × three modes × six schedules = 144 trials, 48 per mode. Each fresh Gateway has documents A and B: different tenants, same exact query, different synthetic answer markers; both initially version 1. Owner A and peer A can read doc A; reader A has no document grants; owner B can read doc B. All source responses carry document provenance for independent authorization checks. Fixture variants are coverage, not independent reliability replications.

1. `repeat`: owner A asks twice. Second response must be current, authorized, and a cache hit. Positive control against disabling reuse.
2. `denied`: reader A asks with an empty cache. Must be 403 with no answer generation. Negative authorization control.
3. `cross_tenant`: owner A warms the cache; owner B asks the same query in tenant B. B's authorized source is doc B; returning doc A is unauthorized, even if the text seems relevant.
4. `same_tenant_scope`: owner A warms; reader A asks the same query in tenant A. Reader has no authorized document.
5. `revoked`: owner A warms; remove A's grants; owner A repeats the request. Previously permitted content is no longer authorized.
6. `source_update`: owner A warms; update doc A to fixture value A2, version 2; owner A repeats. Returning A1 is stale but still authorized by document ID. Keep this freshness outcome separate from a permissions leak.

Shuffle the 144 cells with seed 20261118. One primary matrix only, no silent retry, dropped cell or post-result fixture tuning. These are synchronous Python calls to a real in-memory cache implementation, not HTTP traffic, live RAG sessions, semantic-neighbor matches or LLM generations. There are no network requests or external targets in the measured matrix.

## Outcomes, controls and validation

Primary security outcome: last response with status 200 whose document ID is outside the last request's current eligible set, count/24 per mode (cross_tenant, same_tenant_scope, revoked; eight each). Also report per-scenario count/8. Freshness: last permitted source_update response not equal to the current eligible document's id/version/value, count/8, separate from security. Positive repeat control requires a current authorized second answer with cache_hit True in 8/8; cold-denial control requires 403, no hit, body None and generations 0 in 8/8. Count last responses that satisfy the expected status/provenance/content contract across all 48 trials per mode. Keep all first/second outputs, request arguments, mutations, pre/post snapshots and raw scores; count failures honestly.

Before measurement, the protected eight-check suite validates repeat reuse, cross-tenant behavior of all three modes, scope/revocation baselines, source-update invalidation, correct cold denial/no negative caching, reuse by a different principal with the same context, value-change invalidation without version increment and caller-copy isolation/invalid mode. The primary scorer must pass positive, negative, freshness, missing-response and malformed-boolean controls. Acceptance and controls are not counted as primary trials. Protocol, fixtures/order, implementation, tests, harness, scoring and auditor are hashed and committed before the single matrix.

A separate auditor imports neither cache.py nor harness.py. It reconstructs every source/grant transition from raw requests/mutations, validates each request's before/after snapshot, replays the specified cache policy independently, and recomputes permission/freshness/control counts. It checks exact fixture/order coverage and all frozen hashes. Any missing cell, inconsistent snapshot, bad control or changed frozen source blocks a publication-ready result. The auditor's predicted state must agree with saved observations; predictions alone are not measurements. Do not infer population rates or claim an actual vendor vulnerability from these selected counterexamples.

Current Codex subscription and Mac only, no measured model calls, new models, paid APIs or rented compute. No user production project, ACL, browser, real cache or publishing automation is modified.
